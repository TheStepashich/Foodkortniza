# Фудкортница — план мини-браузера для фудкортов (Android)

> Не юридическая консультация. Перед публикацией в RuStore/Google Play нужна проверка по 152-ФЗ, товарным знакам и правилам сторов.

> **Обновление архитектуры:** ниже описан исходный план с отдельными процессами `:tab0..:tab3`. Практика показала, что Android убивает фоновые процессы и смена task даёт сдвиг/перезагрузку. Реализация переведена на **один процесс** с кэшем WebView на 4 вкладки; сессии/куки между магазинами теперь общие. Остальное (панель, каталог, двойное закрытие) сохранилось.

## Концепция (финальная на текущий момент)

- **Только Android**, без инкогнито.
- Нижняя панель: **4 кнопки-вкладки по умолчанию + «+» справа**. Кнопка = фавикон + название магазина. Адрес сайта в интерфейсе не показывается.
- «+» открывает **каталог интернет-магазинов еды** — выбираем магазин из списка, он становится новой вкладкой-кнопкой. Панель при необходимости прокручивается горизонтально; «+» остаётся закреплённым справа.
- Вкладки можно закрывать. При закрытии — **двойное предупреждение** и безвозвратное удаление куки/данных этой вкладки.
- Каждая вкладка держит свой WebView в памяти и восстанавливается на последнем адресе; сессии/куки общие для всех вкладок.
- Оплата и авторизация остаются на сайте магазина; приложение не видит пароли и данные карт.

### Масштабирование встроенных заготовок

Да, встроенные заготовки из `stores.json` **масштабируются**: каталог — это данные, а не код. Добавление магазина не требует правок в интерфейсе или бизнес-логике.

Схема записи магазина:

```json
{
  "id": "papajohns",
  "title": "Папа Джонс",
  "entryUrl": "https://papajohns.ru/",
  "allowedHosts": ["papajohns.ru", "*.papajohns.ru"],
  "categoryId": "pizza",
  "searchKeywords": ["папа джонс", "papa johns", "пицца"],
  "priority": 20,
  "enabled": true,
  "emoji": "🍕",
  "color": "#0B5EA7",
  "note": "Короткая справка для каталога"
}
```

- `enabled: false` временно скрывает магазин (например, сайт сломался или перестал принимать заказы) без удаления записи.
- `priority` задаёт порядок в каталоге; `defaultIds` задаёт четыре стартовые вкладки — оба списка меняются в конфиге.
- `categories` и `searchKeywords` создаются там же: экран каталога получает поиск и фильтры «в готовом виде» и не знает про конкретные бренды.
- `allowedHosts` используется WebView для whitelist доменов; для «Своей ссылки» список строится из хоста введённого адреса.
- `schemaVersion` + миграции позволяют менять структуру без сброса пользовательских вкладок.

Порядок обновления каталога:

1. Сейчас — `stores.json` как встроенный asset в APK; обновление каталога приходит вместе с версией приложения.
2. Позже — тот же JSON по HTTPS с версией/подписью и кэшем, с fallback на встроенный. Пользовательские вкладки и их данные обновление каталога не трогает.

Размер каталога не влияет на память: в памяти только открытые вкладки (лимит 4), остальные — записи в локальной БД.

## Архитектура Android

```
Фудкортница
├── BottomBar (HorizontalScrollView + закреплённый «+»)
│   ├── [🍔 Burger King] [🍕 Додо] [🔥 Грильница] [🍗 Гриль №1]
│   ├── добавленные вкладки (из каталога) — справа от четырёх базовых
│   └── [+] → экран «Каталог магазинов еды» (поиск, категории, добавление)
├── Экран каталога
│   ├── список из stores.json (встроенный), иконка/фавикон + название + краткое описание
│   ├── нажатие → создать вкладку и сразу открыть её
│   └── повторное добавление уже открытого магазина → перейти на существующую вкладку
├── Вкладка = отдельный процесс Android + отдельный WebView
│   ├── android:process=":tab0..:tab3" — фиксированные слоты в манифесте
│   ├── WebView.setDataDirectorySuffix("tab_<tabId>") ДО создания WebView
│   ├── изолированы CookieManager, localStorage, IndexedDB, история
│   └── состояние (id, title, favicon, lastUrl, order) — в локальной БД/SharedPreferences
├── Закрытие вкладки
│   ├── диалог 1: «Закрыть вкладку «X»?»
│   ├── диалог 2: «Куки и данные вкладки будут удалены. Отменить нельзя»
│   └── подтверждение → убить процесс → удалить data directory → убрать кнопку
└── Сайт магазина внутри WebView
    ├── оплата/3DS/авторизация — на стороне сайта
    ├── переход на сторонний домен — заглушка с полным именем хоста и кнопкой «Продолжить/Назад»
    └── запрет schem: javascript:, file:, data:, tel: и т.п.
```

### Почему отдельный процесс на вкладку

В Android данные WebView (куки, localStorage, IndexedDB) хранятся **на уровень процесса приложения**, а не отдельного `WebView`. Чтобы вкладки не делили сессии, каждая вкладка работает в отдельном процессе. Имена процессов в манифесте статичны, поэтому используются 4 фиксированных слота `:tab0`–`:tab3`, которые назначаются вкладкам по LRU. Суффикс каталога WebView — `tab_<tabId>`, то есть привязан к вкладке, а не к слоту: при переиспользовании процесса чужие данные не подхватятся. Иначе вход в один магазин «затечёт» в другой.

Практическое следствие: нельзя держать в памяти 20 WebView. Устанавливаем лимит **4 активные вкладки** с выгрузкой по LRU: при переключении на пятую процесс самой давно не использованной вкладки убивается, но её данные остаются на диске и восстанавливаются при возврате. При закрытии данные удаляются физически. Это достаточно для сценария «заказывать не везде одновременно».

### Модель вкладки

```json
{
  "id": "uuid",
  "storeId": "burgerking",
  "title": "Burger King",
  "favicon": "https://burgerkingrus.ru/favicon.ico",
  "lastUrl": "https://burgerkingrus.ru/cart",
  "processSuffix": "tab-uuid",
  "order": 0,
  "isDefault": true,
  "createdAt": "2026-11-24T00:00:00Z"
}
```

- `lastUrl` сохраняется при переключении/сворачивании — вкладка возвращается туда, где была.
- `isDefault: true` у четырёх стартовых; по вашей формулировке **все вкладки, включая стартовые, можно закрывать**.
- После закрытия стартовой вкладки «+» может добавить её заново из каталога.

### Добавление из каталога

1. Нажать «+» → экран каталога.
2. Выбрать магазин → создать запись вкладки с уникальным `id` и назначить свободный слот `:tab0`–`:tab3`.
3. Кнопка-вкладка появляется в панели; WebView открывает стартовый URL магазина.
4. Если магазин уже открыт — просто переключиться на его вкладку (не создавать копию).
5. Внизу каталога — форма **«Своя ссылка»**: название + https-адрес. После сохранения создаётся обычная вкладка со своим процессом; она ничем не отличается от вкладок из каталога.
6. При добавлении своей ссылки показывается полный домен и предупреждение, что сайт не проверялся приложением.

### Безопасность без адресной строки

Раз адрес не показан, пользователь не видит, где находится:

- встроенные магазины — только проверенные https-домены из `stores.json`;
- «Своя ссылка» — только `https://`, без `localhost`, private IP и схем `javascript:`, `file:`, `data:`; при добавлении показывается полный домен и предупреждение, что сайт не проверялся;
- `shouldOverrideUrlLoading`: разрешать http(s) для домена текущей вкладки и его поддоменов, а также домены эквайринга/3DS при редиректе;
- при переходе на другой хост — полноэкранная заглушка с полным доменом, кнопками «Продолжить» и «Назад»;
- фавикон и название в кнопке вкладки помогают понять, где пользователь; по долгому нажатию показывается карточка с полным доменом;
- при первом входе в аккаунт/оплату — одноразовый дисклеймер: «Данные вводятся на сайте магазина. Приложение их не хранит».

## Риски

| Риск | Снижение |
|---|---|
| Утечка сессий между вкладками | Отдельный процесс + `setDataDirectorySuffix` на вкладку; автотест изоляции |
| Нехватка памяти при многих вкладках | LRU-лимит 4 активных WebView, выгрузка остальных с сохранением данных на диске |
| «Своя ссылка» окажется фишинговой | Только https, подтверждение полного домена при добавлении, заглушка при смене хоста, без нативного моста |
| Стор отклонит как «обёртку» | Каталог, вкладки, изоляция, нейтральная иконка, дисклеймер |
| Сайт заблокирует WebView или сменит адрес | Обновление каталога, без обхода защиты |
| Пользователь не понимает, что платит на стороннем сайте | Дисклеймер при входе/оплате, заглушка на стороннем домене |
| Случайное закрытие вкладки с потерей корзины | Двойное предупреждение с явным текстом про удаление данных |

## Зафиксированные решения

- Платформа: **только Android**, без инкогнито.
- Панель: 4 кнопки-вкладки + «+», без адресной строки.
- «+» → каталог магазинов еды + форма «Своя ссылка».
- Все вкладки закрываются с двойным подтверждением и удалением данных.
- Активных WebView в памяти: **до 4**, дальше выгрузка по LRU.
